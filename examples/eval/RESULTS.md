# Eval scorecard — first recall/precision pass

**Recall 38/38 (100%)** (juror caught its planted defect) · **Precision 38/38 (100%)** (juror stayed quiet on the clean twin). 76 live juror reviews, deterministically graded against `expect_match`.

## What this proves (and what it does NOT)

A clean sweep here means every juror is **correctly wired and functional** — none is misconfigured into missing its own canonical defect, and none is trigger-happy on obviously-clean code. That is a real, useful floor: a broken or mis-scoped juror would fail it.

It does **NOT** prove real-world principal-level recall, for one structural reason: **the fixtures were generated by agents reading the same review skills**, so each planted defect is the textbook version of that juror's blocking bar. The juror is graded on catching the defect its own skill describes — a self-referential test. Real defects are subtler and not phrased the way the skill expects.

So treat these numbers as a **wiring/smoke floor**, not a quality ceiling. To measure true recall, the next eval needs **independent, adversarial fixtures** (below).

## Next eval to find real weaknesses

- **Adversarial fixtures**: defects authored independently of the skills, phrased *unlike* the blocking bar, plus subtle/partial defects near the blocking threshold.
- **Hard precision cases**: clean code that superficially resembles the defect (e.g. a parameterized query next to a safe f-string log) to stress false-alarm rate.
- **Cross-lane fixtures**: a defect in lane A handed to lane B's juror — it must stay silent (lane discipline).
- **Multi-defect fixtures**: several issues at once, to test triage/ranking.
- Graded the same way (`tests/run-eval.sh`), tracking per-lane recall/precision over time.
